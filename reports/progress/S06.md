## 2. Tóm Tắt Mục Tiêu & Yêu Cầu Kỹ Thuật

- **Đầu vào (Inputs):** DDL schema G1 (`contracts/migrations/001_initial_g1_schema.sql`), Data Contracts Swift (`DataContracts.swift`), Snapshot manifest từ S05.
- **Đầu ra kỳ vọng (Expected Outputs):**
  - Canonical `ProjectStore` Swift actor là đường commit duy nhất vào SQLite WAL.
  - Worker tuyệt đối không nhận kết nối ghi hoặc write handle vào DB chuẩn.
  - Pragmas bắt buộc: `PRAGMA foreign_keys = ON;`, `PRAGMA journal_mode = WAL;`, `PRAGMA busy_timeout = 3000;`.
  - Transaction ngắn (`BEGIN IMMEDIATE` ... `COMMIT` / `ROLLBACK`).
  - Idempotency journal (`idempotency_journal`): nhận diện lặp lệnh, trả kết quả đã commit trước đó mà không tạo revision rác.
  - Revision conflict: kiểm tra `expectedRevision` so với `current_revision` của project, ném lỗi rõ ràng nếu có tranh chấp (optimistic concurrency).
  - Fact confirmation: sinh snapshot revision mới với `review_status = .confirmed`, ghi vào bảng `approvals`, giữ nguyên `origin=user` và `epistemic_status=reported`.
  - WAL checkpoint: hàm `checkpointWAL()` hỗ trợ checkpoint passive định kỳ.
- **Ràng buộc cốt lõi (Core Invariants):**
  - `DATA-03`: Swift Core là nơi duy nhất commit canonical DB. Worker chỉ nhận RPC và trả typed payload.
  - `DATA-04`: Lịch sử revision là append-only bất biến. Confirm fact không bao giờ biến claim thành observed hoặc visual_model.

### 3.2. Điểm nhấn kiến trúc & Concurrency Safety
1. **Swift 6 Actor Isolation & Sendable C Handle:**
   - Sử dụng wrapper `final class SQLiteDatabaseHandle: @unchecked Sendable` để quản lý an toàn vòng đời con trỏ C `sqlite3*`, đóng kết nối tự động trong `deinit` mà không vi phạm quy tắc Concurrency của Swift 6.
2. **Nguyên tắc Transaction Ngắn & Phân Tách Internal:**
   - Tránh deadlock lồng transaction (nested transaction error `cannot start a transaction within a transaction`): phân tách các hàm nội bộ `saveClaimInternal` chạy trong context transaction hiện hữu, trong khi các API công khai `saveClaim`, `createProject`, `createWorkday`, `confirmFact` bảo đảm tính nguyên tử (atomic) toàn vẹn.
3. **Idempotency Journal:**
   - Tra cứu bảng `idempotency_journal` trước khi ghi; nếu `operation_id` đã tồn tại, lập tức giải mã JSON và trả kết quả cũ mà không sinh revision mới hay sửa đổi trạng thái.
